# Vividuss requirements

Approved foundation: Next.js dashboard, Express authorization/business API, PostgreSQL and Prisma, Clerk authentication, and Puck editing. One generic renderer must eventually resolve customer websites by verified hostname. Publishing validates and snapshots JSON; it never generates customer-specific React source or deployments.

Target: canonical versioned documents, shared React views/styles, immutable publication revisions, organization tenancy/RBAC, responsive rendering, server-rendered SEO, and reversible validated JSON operations for future AI tools and design recipes.

Future AI scope includes AI Touch, generated sections/sites, preview/apply/reject/undo, similarity recommendations, an AI gateway/model routing, usage metering, subscription credits/limits, SEO and responsive repair. Forms, bookings, commerce and enterprise capabilities remain later tenant-scoped business modules. AI must propose validated JSON operations, not arbitrary executable code.

Compatibility: preserve existing template/site JSON, legacy section rendering, custom media URLs and global layouts until migration is verified. No silent conversion.

Milestone 1: startup/environment, reproducible verification, layout/category repairs, bounded JSON requests, reliable editor flush/publish, and immediate security controls. No AI, hostname renderer, tenant redesign, monorepo restructure, or populated-database migration.
