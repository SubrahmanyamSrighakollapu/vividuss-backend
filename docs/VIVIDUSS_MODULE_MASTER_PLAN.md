## Architectural constraints across modules

Retain Next.js 16, Express 5, Prisma 6/PostgreSQL, Clerk, Puck, React and current repository applications. JSON is data: no eval, arbitrary module loading, customer React source generation, or customer-specific builds. `shared/website-contract` is a small dependency-free cross-runtime boundary, not a new application/workspace.

Later organizations must resolve ownership server-side rather than trust JSON tenant IDs. Business components must store stable resource references; public rendering must resolve only explicitly published/public capabilities. Provider keys and privileged business operations never belong in page JSON. AI must propose bounded contract-valid JSON operations under existing authorization and concurrency rules.

Publication must eventually freeze page documents, site metadata, layout, theme and registry/schema compatibility into a revision selected by an atomic website pointer. Hosts must resolve a verified site/revision, not alter the editor contract. Existing draft/public data remains intact while these additive designs are approved and rehearsed.

## Milestone 3 status update

Publication/history now includes immutable records, restoration provenance, optimistic website draft counters and website-owned frozen chrome, behind a disabled rollout gate. The generic slug renderer resolves active revisions when enabled. Organizations, billing, AI, domains and broader business module approval states above remain unchanged.
